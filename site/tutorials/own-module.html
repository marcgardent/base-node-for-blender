Write your own module

The standard library is a folder of .bn files: math.bn, merge.bn, toon.bn… Each is a module, and a use line brings its graphs into another file. Nothing sets them apart from a file you write. This tutorial starts from one file of dunes, moves its waves into a module, gives the module what the standard library's have, a head, a version, documented inputs, builds it on the standard library, and installs it in Blender.

Before you start

You need Blender 5 and the Base Node add-on. Everything here is free: the language, the add-on and the standard library.

A step here is not one file but a folder of them: step2/dunes.bn uses step2/waves.bn, which must lie beside it. Each block below is one file, its code beside the nodes it builds; the cards at the end of each step are its files to download, named as Blender will look for them. To try a step:

  1. Download its files into one folder, a folder per step: two files of the same name from two steps would become waves (1).bn, which no use waves finds.
  2. Import the scene: File > Import > Base Node (.bn), and select dunes.bn, and sand.bn from step 3 on; not waves.bn, which dunes.bn finds by itself. Or drop dunes.bn from your file manager onto Blender's 3D Viewport, and keep Instantiate the Example; from step 3, import sand.bn first.
  3. See it: without the drop, add a plane and give it a Geometry Nodes modifier whose group is dunes: the graph makes its own ground.

The pictures are rendered from these exact files by render.py, which imports each folder with the add-on's own File > Import, under a low sun from the west.

1. One file

Everything starts in one file. lift raises each point of a mesh by a sine of its x: a wave every 2π / frequency metres, height above and below. Sand is a material. dunes makes a square grid, lifts it, and sets the material.

step1/dunes.bn: dunes, lift, Sand

  • A graph called is a node group. dunes calls lift as it calls Grid: Blender builds lift into a node group of that name, and dunes holds a Group node of it.
  • A material is set by its name. shader(material: true) graph Sand is the node tree of the material Sand, and SetMaterial(material: Sand) names it.

This works, and for one scene it is enough. But lift has nothing to do with this scene: any ground, any mesh could use it. Copied into another file, it would be two lifts to fix the day one of them has a bug. A graph worth reusing belongs in a file of its own, that other files point to.

2. The waves on their own

lift moves, as it is, into waves.bn, next to dunes.bn:

step2/waves.bn: lift

and dunes.bn says where to find it, in a use line at its top:

step2/dunes.bn: dunes, Sand

That is all a module is: a .bn file. use waves asks for the file waves.bn; Blender looks for it, in this order:

  1. A text of the .blend named waves.bn, in Blender's Text Editor.
  2. Next to the file imported: waves.bn in the folder of dunes.bn. This is how step 2 finds it.
  3. The Module Folder of the add-on's preferences (step 6).
  4. The standard library the add-on ships: math.bn, merge.bn and the others are found here, last.

A pasted text (Ctrl+Shift+V in a node editor) has no folder: it finds its modules in the texts of the .blend, the Module Folder and the standard library only. To skip the search, use waves from "//lib/waves.bn" names a file by its path from the .blend, which must be saved; an absolute path or a URL is refused.

Three ways to say it

LineThe callWhat it brings
use waves (lift)lift(…)The graphs named in parentheses, by their own names.
use waveswaves::lift(…)Every graph, behind the name of the module (step 6).
use waves as ww::lift(…)The same, behind a shorter name.

The comment lines at the top are the file's head: // @module waves is the name of the module, the name Install as Library gives the file (step 6), and the name of the file you download from this page. Without it, a file is named after its last graph: lift.bn, which use waves would not find.

In Blender, lift is the same node group as before, with one difference: it remembers where it comes from, in its custom property base_node_module, waves. So when the text view of dunes writes the tree back as text, it writes use waves (lift) and the call, not the body of lift.

The views on this page read one file at a time. In the view of dunes.bn, lift is a node with the inputs the call gives it; its body is in the view of waves.bn.

Watch out: import dunes.bn, not waves.bn too. Imported on its own, waves.bn builds lift again as a group of its own text, and the group forgets the module it came from.

3. The material in a third file

The material moves too, into sand.bn. But not as a module: use brings node groups, and a material is no node group. dunes.bn has no use sand; it keeps SetMaterial(material: Sand), a name, which finds the material Sand of the .blend, whichever file made it.

step3/sand.bn: Sand

step3/dunes.bn: dunes

So sand.bn must be imported before dunes.bn, or with it: choose both in one File > Import, and the add-on imports again, after the others, a file that named a material it did not find yet. Imported alone, dunes is built with a warning for the missing material, and the ground has no material. waves.bn is unchanged, still found beside dunes.bn.

4. A module others can read

waves.bn works, for us. Someone else, opening it, does not know what frequency is counted in, which version they have, or whether it will build in their Blender. The modules of the standard library answer all three in the same places. Here is the head of math.bn: 

// Base Node Standard Library — Module math
// @module math
// @version 1.0.0
// @target blender
// @edition 2026
// @description Mathematical toolkit for Geometry Nodes: shaping curves, waves, vectors, SDFs, and noise distributions

waves.bn takes the same head, and the same habits below it:

step4/waves.bn: lift

LineWhat it saysWho reads it
@moduleThe module's name, an identifier: its file is <name>.bn.Install as Library, the file a download is named
@versionThe version of the file, as its author numbers it.The drop dialog shows it
@targetWhere it promises to build: blender is every version of Blender this add-on promises. A version alone, blender@5.3, is a promise too: the module toon makes it.base-node check waves.bn: OK (blender); the CI holds the standard library to it
@editionThe edition of the language it is written in, 2026.Every reader: a later edition is refused rather than misread
@title, @author, @licenseFree text, shown to whoever opens the file.The drop dialog
@descriptionOne line on what the module does.The standard library's manifest and reference
@offerlibrary: it may be installed as a module (step 6); groups: its graphs may be imported into a .blend.The drop dialog

Then, inside the graph:

  • A description. The string at the head of a graph becomes the node group's description in Blender.
  • Each input documented. height: Float(subtype: DISTANCE, description: "…"): the description is the input's tooltip, and the subtype is Blender's, the unit it shows: DISTANCE in metres, ANGLE in degrees though the value is in radians, FACTOR as a slider.
  • Ranges. = 0.2 in 0.0..: a default, and the least value Blender lets you type in the modifier's panel. A height below zero would only turn the waves over.
  • Sections. A comment written // ---- Lifting a mesh ---- groups the graphs that follow. In the standard library, the reference page of each module (stdlib-math.html) is written from these: the head's description, the comment under it, a section per // ---- line, and per graph its description and a table of its inputs, with their defaults and ranges.

lift also gains an input, direction, to run its waves at any angle. Its default, 0, is the x axis: a call written for step 3 means the same thing, and draws the same waves. That is the rule the standard library keeps between its versions:

VersionWhen
Major, 2.0.0A text that built before builds another tree: a graph, an input or an output removed or renamed, a default changed.
Minor, 1.1.0New graphs, new inputs with a default.

direction arrives before the first version, so waves starts at 1.0.0. To retire a graph without breaking its callers, mark it geometry(deprecated: "use drift") graph lift(…): it still builds, and each call of it is a warning.

5. A module that uses the standard library

A sine is no dune. A dune climbs a long gentle slope on the side the wind comes from, and falls down a short steep one behind its crest. waves 1.1.0 adds two graphs for it, and writes neither from scratch: a module may use others, the standard library's first.

step5/waves.bn: profile, drift, lift

  1. use math (ease_in_out, fbm), the line every reader of this file needs to build it. The graph "ease in out" has a name with spaces: a use names it by its key, ease_in_out, and calls it so.
  2. profile is one dune across a period from 0 to 1: t / windward climbs to 1 over the first 75 %, (1 − t) / (1 − windward) falls back over the rest, and their minimum is a sharp triangle leaning downwind. ease_in_out rounds it: flat in the trough, flat on the crest.
  3. drift raises each point by the profile of how far it lies downwind, in wavelengths. fbm, the fractal noise of math, shifts that distance by up to meander metres: the crests wander instead of running straight.
  4. lift stays as it was in 1.0.0: new graphs, no input changed, a minor version.

dunes.bn now calls drift. And profile has a second use: wind ripples, the same shape, twelve to the metre, in the material.

step5/sand.bn: Sand

Sand is a shader tree, and profile was written as a geometry graph. A graph a use brings may be called from a tree of another kind: Blender builds it again for that kind, in a group of its own, profile (Shader), and ease in out (Shader) with it. This works because profile is only math, which every tree has. drift, with its SetPosition, could not be called from a material: Blender would refuse it and say which node the shader tree lacks.

step5/dunes.bn: dunes

6. Install it

Found next to the file that uses it, waves serves the files of one folder. Installed, it serves every .blend:

  1. Choose a Module Folder: Edit > Preferences > Add-ons > Base Node > Module Folder, any folder of yours.
  2. Drop waves.bn from your file manager onto Blender, and pick Install as Library. Its head offers it (@offer library). The dialog shows the title, author, license and version, and where the file goes: use waves ← …/waves.bn. It copies the file there under the name of its @module, never over another text of that name unless you tick Overwrite.

Now step 6 has no waves.bn beside it. Its dunes.bn uses the whole module, use waves, and calls drift twice by its full name: long dunes from the west, then small ones across them, blown 46° from the x axis (direction: 0.8, in radians).

step6/dunes.bn: dunes

sand.bn is the same as in step 5: its use waves (profile) finds the installed module too. render.py installs waves.bn into an empty Module Folder with the dialog's own operator, then imports this folder.

Where the module was found matters again when Blender writes a tree back as text. A group from the Module Folder reads back as use waves (drift). A group found next to an imported file keeps that file's full path: in the same session, the text view writes use waves (drift) from "/…/step5/waves.bn", a path Blender accepts only until it quits; in a later session, it writes the bodies of drift and profile into the text instead. A module you share is one to install.

The standard library, read again

Everything above is how the standard library is made. Each of its modules is one file of stdlib/, with the head of step 4, built on others by use as in step 5: curves2d.bn starts with use math (bump, fbm). The add-on ships the folder, and it is the last place a use looks. Its manifest is read from the heads: each module's name, version, targets and description, and its dependencies, the modules its use lines name. Adding a module is adding its file.

The order of the search has one more consequence: a module of yours is found before the standard library's. A math.bn in your Module Folder would hide the one every use math expects. Give your modules names of their own.

Take it to Blender

The finished module, and the scene that uses it. Download the three files into one folder, import dunes.bn and sand.bn, or install waves.bn first and take dunes.bn and sand.bn of step 6 anywhere.
